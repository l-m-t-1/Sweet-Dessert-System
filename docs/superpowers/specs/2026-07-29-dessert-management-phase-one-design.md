# 甜品管理系统第一阶段设计

## 1. 目标

在保留现有 MySQL 数据的前提下，完成甜品分类与甜品信息的数据库闭环，提供图片上传、增删改查、分页筛选、上下架和实时库存统计，并将 Vue 后台统一改造成“深焙可可”视觉风格。

第一阶段完成后，管理员可以从登录页进入后台，管理分类和甜品，上传甜品图片，并在首页看到数据库实时统计数据。

## 2. 范围

### 2.1 包含

- 美化登录页、后台布局、首页、分类管理页和甜品管理页。
- 保留现有 `user` 与 `dessert` 数据。
- 新增甜品分类表。
- 为甜品补充分类、库存、上下架状态和时间字段。
- 分类新增、查询、重命名和删除。
- 甜品分页查询、名称搜索、分类筛选、新增、编辑、删除和上下架。
- 后端本地图片上传与静态访问。
- 首页实时统计甜品数量、分类数量、总库存和低库存数量。
- 首页展示低库存甜品列表。
- 统一接口错误处理和前端消息提示。

### 2.2 不包含

- 订单管理。
- 库存出入库流水。
- 多角色细粒度权限。
- 云对象存储。
- 面向顾客的商城页面。

## 3. 技术方案

### 3.1 总体实现顺序

采用纵向完整实现方式：

1. 检查实际 MySQL 表结构并通过 Flyway 执行保留数据的版本化迁移。
2. 完成分类后端与分类管理页面。
3. 完成甜品后端与甜品管理页面。
4. 完成图片上传与静态资源访问。
5. 完成首页实时统计。
6. 统一视觉与交互细节。
7. 执行后端、前端和完整业务流程验证。

每个模块都在进入下一模块前完成自动化测试和接口验证。

### 3.2 后端结构

后端继续使用 Spring Boot、MyBatis Plus 和 MySQL，并按职责拆分：

- `controller`：HTTP 路由、请求参数接收和响应状态。
- `service`：分类关联检查、价格库存校验、上下架和统计等业务规则。
- `mapper`：MyBatis Plus 数据访问。
- `entity`：数据库表映射。
- `dto`：新增、编辑和筛选请求，避免直接使用实体接收外部数据。
- `exception`：业务异常与统一异常响应。
- `config`：跨域、静态图片目录与 MyBatis Plus 分页配置。

保留现有 `/user/login` 接口。分类、甜品、上传和统计接口分别使用 `/category`、`/dessert`、`/upload` 和 `/dashboard` 前缀，避免对现有登录流程做无关改造。Flyway 使用基线版本 0 接管现有数据库，第一阶段迁移从版本 1 开始，确保已有表不会被重新创建或清空。

## 4. 数据库设计

### 4.1 `category` 表

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | `BIGINT` | 自增主键 |
| `name` | `VARCHAR(50)` | 非空、唯一 |
| `create_time` | `DATETIME` | 非空 |
| `update_time` | `DATETIME` | 非空 |

### 4.2 `dessert` 表扩展

保留现有字段，并补充：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `category_id` | `BIGINT` | 关联分类 |
| `stock` | `INT` | 非空、默认 0、不得小于 0 |
| `status` | `TINYINT` | 非空、默认 1；1 上架，0 下架 |
| `create_time` | `DATETIME` | 非空 |
| `update_time` | `DATETIME` | 非空 |

`price` 在 Java 中使用 `BigDecimal`。分类仍被甜品使用时，业务层拒绝删除分类。数据库迁移必须保留现有用户和甜品数据，并为旧甜品补充默认分类、库存和状态。

## 5. 图片上传

- 图片写入 `backend/uploads/desserts/`。
- 数据库仅保存 `/uploads/desserts/<唯一文件名>`。
- Spring Boot 将 `/uploads/**` 映射到本地上传目录。
- 仅允许常见图片 MIME 类型和扩展名。
- 单张图片限制为 5 MB。
- 文件名使用随机 UUID，禁止使用用户原始文件名作为保存路径。
- 上传失败返回明确的中文错误。

前端先上传图片，获取访问路径后，再将图片路径与甜品表单一起提交。

## 6. API 行为

### 6.1 分类

- 获取分类列表。
- 新增分类。
- 修改分类名称。
- 删除分类。
- 分类名称去除首尾空格后不能为空。
- 分类名称重复返回业务错误。
- 分类仍有关联甜品时拒绝删除。

### 6.2 甜品

- 按页查询甜品。
- 按名称模糊搜索。
- 按分类筛选。
- 新增甜品。
- 编辑甜品。
- 删除甜品。
- 切换上下架状态。
- 名称和分类必填。
- 价格不得小于 0。
- 库存必须为非负整数。
- 分类必须真实存在。

### 6.3 首页统计

统计接口返回：

- 甜品总数。
- 分类总数。
- 总库存。
- 库存小于或等于 5 的甜品数量。
- 最多 5 条低库存甜品记录。

## 7. 前端设计

### 7.1 视觉规范

采用“深焙可可”风格：

- 页面背景使用深棕黑色。
- 卡片使用略浅的深棕色和柔和边框。
- 琥珀金用于主按钮、关键数字和导航选中状态。
- 正文使用暖白与低对比灰棕色。
- 圆角保持适中，避免过度卡通化。
- 适配常见桌面和笔记本宽度；较窄屏幕可收起侧边栏。

### 7.2 登录页

- 统一品牌与配色。
- 用户名和密码必填校验。
- 登录按钮显示提交状态，防止重复提交。
- 登录失败使用 Element Plus 提示。
- 登录成功保存必要的用户展示信息并进入首页。

### 7.3 后台布局

- 左侧导航包含首页、甜品管理和分类管理。
- 顶部展示页面标题、当前用户和退出操作。
- 使用路由元信息显示标题和面包屑。
- 未登录访问后台页面时返回登录页。

### 7.4 首页

- 四张统计卡展示实时数据库数据。
- 展示低库存甜品列表。
- 提供进入甜品管理和分类管理的快捷入口。
- 统计加载失败时显示可重试状态。

### 7.5 分类管理

- 表格展示分类名称和更新时间。
- 支持新增、重命名和删除。
- 删除前二次确认。
- 有关联甜品时展示后端返回的明确原因。

### 7.6 甜品管理

- 支持名称搜索、分类筛选和分页。
- 表格展示图片、名称、分类、价格、库存、状态和操作。
- 新增与编辑使用弹窗表单。
- 图片使用上传组件并显示预览。
- 上下架使用状态开关。
- 删除前二次确认。

### 7.7 请求封装

全部接口通过 `frontend/src/api/request.js` 调用，不在页面中写死后端地址。开发环境由 Vite 将 `/api/*` 代理到 Spring Boot 并移除 `/api` 前缀，例如前端 `/api/dessert/page` 对应后端 `/dessert/page`；`/uploads/*` 保留路径直接代理到 Spring Boot。这样可以减少跨域配置与环境切换问题。

## 8. 错误处理

后端统一处理：

- 参数校验错误。
- 业务规则错误。
- 数据不存在。
- 文件格式和大小错误。
- 数据库约束错误。
- 未预期服务器错误。

错误响应包含稳定的 HTTP 状态和可展示的中文消息。前端统一处理网络失败与接口错误，并为加载、提交、空数据和失败状态提供明确反馈。

### 9.1 自动化验证

- 分类名称校验、重复检查和关联删除检查。
- 甜品价格、库存、分类校验。
- 甜品分页、搜索和分类筛选。
- 上下架切换。
- 首页统计计算。
- 图片类型、大小和唯一文件名。
- 后端 Maven 全量测试。
- 前端核心请求与页面行为测试。
- 前端生产构建。

### 9.2 完整流程验收

在 MySQL、Spring Boot 和 Vue 均启动后，执行：

1. 使用现有账号登录。
2. 新增一个分类。
3. 上传一张甜品图片。
4. 新增一个甜品并关联该分类。
5. 搜索和筛选该甜品。
6. 编辑价格与库存。
7. 切换上下架状态。
8. 验证首页统计与低库存列表同步变化。
9. 删除甜品后删除分类。
10. 检查四个主要页面的深焙可可视觉一致性。
